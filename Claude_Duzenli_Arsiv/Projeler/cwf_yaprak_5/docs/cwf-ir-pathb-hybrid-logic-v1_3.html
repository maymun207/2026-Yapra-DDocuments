IR + Hybrid Retrieval (Path B) — Sequence Logic Reference

IR omurgasının üzerine BM25+vektör hybrid retrieval bindiğinde sistemin alacağı şekil: federated araç uzayları (SAP BAPI'leri, IoT-Ignite cihaz yetenekleri, 1000+ tool) için ikinci çözümleme yolu. Değişmeyen ilke: retrieval ham dili asla görmez — yalnız normalizer'ın kanonik frame'iyle arar. BM25/hybrid, IR'ın rakibi değil, IR'ın arkasına monte edilen ikinci stratejidir.

STATUS: IR-4 FUTURE-STATE CONTRACT — federated backend gerçek olduğunda aktive olur; build order değildir

§1Runtime Sequence — Federated Sorgu Örneği

Tek cümlelik özet: 4 numaralı adımda Resolver Router core tabloda MISS görür ve Yol B'ye deterministik olarak döner — LLM hangi backend'e gidileceğini seçmez. Retrieval sorgusu ham cümle değil, frame'in kanonik terimleridir; SAP BAPI açıklamalarındaki İngilizce teknik terimlerle arası bir çeviri mesafesi kadar kısadır. Morfoloji problemi retrieval'a hiç ulaşmaz — Path A'da çözülmüş olarak gelir.

C1

Qdrant — Hybrid Tool Index

YENİ · Path B çekirdeği
ROL
Federated tool korpusunun tek arama motoru: dense (anlamsal) + sparse (BM25-eşdeğeri lexical) vektörler AYNI koleksiyonda; RRF füzyonu server-side. İki ayrı motor (ayrı BM25 servisi + ayrı vektör DB) bakımlamak yerine tek bileşen — committed tercih.
BAĞLANTI
Girdi: I4 encode çıktısı (upsert) + §1 adım 5 kanonik sorgu. Çıktı: top-k tool referansı → Resolver Router. Tenant izolasyonu: koleksiyon-per-tenant.
CWF-BUGÜN
Yok — Path B ile doğar. Governed DB'deki backend_tools mirror'ı source-of-truth kalır; Qdrant her zaman yeniden inşa edilebilir TÜREV indekstir (kaybı = re-sync, veri kaybı değil).
TWEAK🗄️ retrieval.topK · 🗄️ retrieval.scoreThreshold · 🗄️ füzyon ağırlıkları — governed param, insan · 🤖 indeks inşası/yenilenmesi tamamen makine.
C2

Embedding Service — bge-m3 (self-hosted)

YENİ
ROL
Deterministik encoder — LLM DEĞİL. Tek modelden hem dense hem sparse (lexical ağırlık) çıktısı üretir; çok dilli (TR dahil). Aynı girdi = aynı vektör: test edilebilir, model-agnostiklik hedefini bozmaz.
BAĞLANTI
I4 (korpus encode) + §1 adım 5 (sorgu encode). Kanonik frame terimleri encode ettiği için sorgu uzayı küçük ve kararlıdır.
CWF-BUGÜN
Yok. On-prem/savunma hattında da aynı bileşen (500MB sınıfı, GPU şart değil) — CWF-OnPrem uyumlu.
TWEAK🧱 model versiyonu (değişirse TÜM korpus re-encode — makine yapar, insan versiyon kararını verir).
C3

OPA — Tool-Chain Policy Engine

YENİ · governance
ROL
Retrieval "alakalı mı" sorusuna cevap verir; OPA "izinli mi" sorusuna. Exposure (read|write, write → audited allowWrite), araç-zinciri kuralları ("fabrika verisi çeken tool → dış kanal tool'u YASAK"), tenant scope, rol. Fail-closed: policy'si olmayan tool düşer.
BAĞLANTI
§1 adım 7 — Resolver Router'dan aday set alır, filtrelenmiş set döner. Policy verisi governed DB'den derlenir (tool_annotation overlay → Rego kuralları).
CWF-BUGÜN
ROUTE-GOV-1'in tool_annotation overlay'i (exposure + F80 fail-closed) aynı sözleşmenin CWF-native hali. Path B'de bu sözleşme OPA'ya taşınır/aynalanır — davranış kontratı değişmez, ölçek büyür.
TWEAK🗄️ policy kuralları — SADECE insan, eval-gate'li publish. 🤖 asla policy yazmaz; ihlal denemeleri born-loud loglanır (S41-1).

§5Path B'de Korunan Invariant'lar

(1) Retrieval ham dili görmez — morfoloji Path A'da ölür; sorgu uzayı kanonik ve küçüktür. (2) LLM sayısı artmaz — Path B sıfır yeni LLM çağrısı ekler; belirsizlik noktaları hâlâ ③ ve ⑧'dir. (3) Availability floor kutsaldır — ALWAYS_INCLUDE her yolda union'lanır; Qdrant/OPA outage'ı yalnız federated uzayı düşürür, çekirdek fabrika yetenekleri yaşar. (4) Fail-closed governance — sınıflandırılmamış/policy'siz tool aday sete giremez; write, audited onay ister; ve fail-closed sonucu kullanıcıya HER ZAMAN dürüstçe söylenir (ALT-D). Empty≠zero'nun routing'e dört isimli uygulaması artık bir AİLEDİR: retrieval-empty (ALT-C) · alias-unresolved (ALT-A) · frame-ambiguous (ALT-A) · exposure-ungoverned (ALT-D). (5) Kaynak-türev ayrımı — Supabase source-of-truth, Qdrant yeniden inşa edilebilir türevdir; indeks kaybı veri kaybı değildir. (6) Governed self-improvement deseni genişler ama değişmez — dördüncü ledger (retrieval-miss) da aynı akışı izler: 🤖 önerir → 🗄️ insan + eval-gate → sistem akıllanır. (7) Gözlemlenebilirlik — cwf.retrieval.* span'leri olmadan hiçbir Yol B kararı görünmez sayılır; SET-CONTEXT stage-07 kartı Yol B'de sorgu/top-k/skor/eşik dörtlüsünü gösterir.

§6Yol A vs Yol B — Pros / Cons

Karşılaştırılan: Yol A = IR + deterministik routing tablosu (cwf-ir-sequence-logic-v1) · Yol B = IR + hybrid retrieval (bu doküman). Ham metin üzerinde çalışan saf BM25 router tabloda yoktur — tasarım sürecinde elenmiştir; her iki yol da IR omurgasının üstündedir, fark yalnız çözümleme stratejisindedir.
