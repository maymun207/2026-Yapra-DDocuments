## 3. Architecture spine (the reuse contract)
- **Turn pipeline:** `chat.ts` is an HTTP shell; nine ordered stages live in `api/cwf/_lib/turn/*` over a shared `TurnContext`, then the stream stage (wider contract — owns `res` writes + the retry loop). Every stage is a span (`cwf.stage.NN.*`). Stage ORDER is behaviour, not style.
- **Intent Resolution (IR):** frame → semantic → keyword, in that priority; clarification is ACTIVE and honest. Semantic classifier = a governed small model (DB-first/code-floor via `routerModelId()`); it is a SECOND completion site by explicit precedent — there is still exactly **one `streamText` site** for the chat turn. **`router.frameRouting` code floor = 0 (dark): the frame is extracted and recorded, and steers nothing.**
- **Prompt** = backend-agnostic core modules (identity · safety · time · toolProtocol · grounding · outputFormat) + per-backend domain packs, composed by `buildSystemPrompt(ctx, activeBackends)`; segments governed as `prompt.segment` (L2). `time` is the only non-cached module, by design.
- **LLM** = ONE gateway `streamText` call site (`llm/gateway.ts`; `experimental_telemetry` lives ONLY there; the tool-round ceiling is a governed param). Provider registry DB-first/code-floor; unknown families throw.
- **Knowledge** = `DbKnowledgeProvider` (governed DB = runtime SSOT) with code `referenceSchema` as exactly: seed · reset-target · outage floor. CORE kinds field-locked to Zod + values gated; SOFT kinds DB-extensible. No vector in the deterministic core (that is Path B, and it searches the IR frame, never raw language).
- **Tool information has FOUR sources:** the MCP server's own text · the governed `<backend>.tool_category` map · the `<backend>.tool_annotation` exposure overlay (fail-closed) · the `<backend>.tool_doc` description overlay (append|replace, anti-bloat capped). `backend_tools` is a system-synced MIRROR — missing ≠ deleted.
- **Governance** = `rule_kinds`/`domain_rules`/`rule_versions`/`rule_audit`; publish ONLY via the server-side eval-gate (schema→referential→behavioral), RLS-denied to clients. **Backend identity is DATA** (a row + a pack + one registration — not an enum, not a CHECK).
- **Trust & grounding** (ADR-001/010) = deterministic code, never an LLM judge at runtime. Goal: make a lying backend **harmless** (contained/attributed/quarantinable), not honest. A declaration is a CLAIM, not a warrant; trust is earned per-tool from observed behaviour.
- **Entity topology is DISCOVERED** (ADR-009): descriptors in `backend_entity_layers` are walked into `entity_registry`; zero per-backend literals; call shape read from the tool's own `input_schema`. **Entity coverage gaps are closed by extending discovery, never by alias rows.**
- **Memory** (MEMORY-1) = deterministic multi-signal recall, NO vectors: keyword overlap (one Turkish fold) · entity overlap · recency half-life · importance ladder. Distill is a pure post-response derive with no LLM. Only `agent.memory.retrievalTopK` is governed; `0` issues zero reads.
- **Measurement floor** (MEASURE-READ-HONESTY-1) = a read feeding a measurement, ledger row, actuator or spend/safety fence must distinguish "no data" from "could not read". Three contracts, no fourth shape: throw · `null` · `numberOrNull`. The guard catches failure, never success.
- **Observability** = OTel → self-hosted Langfuse (AWS EC2 behind CloudFront; OTLP/**HTTP** only — gRPC silently fails; force-flush before the response ends). Three systems, never conflated (ADR-004/008): `telemetry_events` = durable governance LEDGER · Langfuse = full scrubbed causal TRACES · `turn_trace_digest` = bounded 14-day DISPLAY-ONLY debug mirror. Join key = the ONE turn id (RULE 28).
- **Persistence** = Supabase repositories behind one service-client proxy; login Supabase-direct; personal MCP secrets owner-scoped RLS; secrets by reference (`apiKeyEnv`, `^MCP_[A-Z0-9_]+$` only). **RLS gates ROWS, not COLUMNS** — a new column on an owner-writable table needs a column grant, not a policy edit (S80/M1F3).
- **ADRs are ground truth for their own subject:** 001 backend trust & provenance · 002 personal-secret RLS · 003 completion robustness · 004 ledger-vs-trace separation · 005 migrations via `supabase db push` only · 006 agent operating modes · 007 Langfuse host trust / secrets never echoed · 008 turn-trace digest · **009 entity topology is discovered** · **010 earned trust: declaration vs observation** · **011 filtered turns cannot mutate** · **012 restriction taxonomy & capability posture**.

## 7. Recurring trap
Every "let's just add X" hides a determinism/safety split: **deterministic/authoritative** (must be exactly correct — code or gated) vs **soft/learned** (advisory — DB-editable). Learning improves how the agent FINDS tools (routing), never what it KNOWS (correctness). Name the split before implementing. Its sibling at the render layer: a guess on an ambiguous key must never look like an answer. **And its sibling at the program layer (S80): an unmeasured claim about the system is an argument, not a result — label it as such in your own prose.**
