## 3. Context

### Data flow: server → client

The current architecture has `ConnTable.tsx` (server) importing `EAIP_CONNECTIONS` directly. For client-side filtering, the data must be in the client. The approach:

```
Server page (async RSC):
  reads lang, imports EAIP_CONNECTIONS + CONN_TYPES + PHASES
  passes all as props to ConnFilterTable ('use client')

ConnFilterTable (client):
  manages [search, typeFilter, phaseFilter] state
  derives filtered subset client-side (useMemo)
  renders filter controls + count + table rows
```

**Why prop-pass, not client import:** `ConnFilterTable.tsx` is `'use client'`. If it imported `EAIP_CONNECTIONS` from `app/_data/`, that 100-item array would be bundled into the client JS. Passing it as a prop keeps the data out of the bundle — it arrives as serialized JSON at runtime only.

**Serialization size:** 100 connections × ~7 fields → ~20KB JSON. Acceptable for an internal tool.

**Type-only imports in client components are safe:** `import type { Connection, ConnType, Phase, Lang } from '@/app/_data/types'` and `import type { StringsForLang } from '@/app/_data/i18n'` — both are erased at compile time, zero bundle impact.

### `ConnTable.tsx` deletion

`ConnTable.tsx` and its inline `ConnRow` function are replaced entirely by `ConnFilterTable.tsx`. The static table is superseded. Delete `ConnTable.tsx` — it is only imported in `eaip/connectivity/page.tsx`, so there are no other consumers.

### Filter behavior

```ts
const filtered = useMemo(() => {
  return connections.filter(conn => {
    if (typeFilter && conn.type !== typeFilter) return false;
    if (phaseFilter && conn.phase !== phaseFilter) return false;
    if (search.trim()) {
      const q = search.toLowerCase();
      return (
        conn.from.toLowerCase().includes(q) ||
        conn.to.toLowerCase().includes(q) ||
        conn.purpose.toLowerCase().includes(q) ||
        (conn.proto ? conn.proto.toLowerCase().includes(q) : false)
      );
    }
    return true;
  });
}, [connections, search, typeFilter, phaseFilter]);
```

All three filters are AND-combined (e.g. type=REST AND phase=core AND search="gateway").

### Count display

```tsx
<p className="font-mono text-xs text-text3 mb-4">
  {filtered.length}{filtered.length < connections.length ? ` / ${connections.length}` : ''} {strings.cnt}
</p>
```

`strings.cnt` is `"connections"` (confirmed in D0.3d). This renders "100 connections" when unfiltered, "12 / 100 connections" when filtered.

### Filter controls design

A `flex flex-wrap gap-3 mt-4 mb-6` row with:

**Search input:**
```tsx
<input
  type="search"
  value={search}
  onChange={e => setSearch(e.target.value)}
  placeholder={strings.search}
  aria-label={strings.search}
  className="bg-bg border border-border rounded-lg px-3 py-1.5 text-sm text-text placeholder:text-text3 focus:outline-none focus:ring-1 focus:ring-text3 min-w-[200px]"
/>
```

**Type select:**
```tsx
<select
  value={typeFilter}
  onChange={e => setTypeFilter(e.target.value)}
  aria-label={strings.allty}
  className="bg-bg border border-border rounded-lg px-3 py-1.5 text-sm text-text focus:outline-none focus:ring-1 focus:ring-text3"
>
  <option value="">{strings.allty}</option>
  {connTypes.map(ct => (
    <option key={ct.id} value={ct.id}>{ct.id}</option>
  ))}
</select>
```

**Phase select:**
```tsx
<select value={phaseFilter} onChange={e => setPhaseFilter(e.target.value)} aria-label={strings.allph} className="...">
  <option value="">{strings.allph}</option>
  {phases.map(p => (
    <option key={p.id} value={p.id}>
      {lang === 'tr' ? p.labelTr : p.labelEn}
    </option>
  ))}
</select>
```

### No-results state

When `filtered.length === 0`:
```tsx
<tr>
  <td colSpan={6} className="py-12 text-center text-text3 text-sm">
    {filtered.length === 0 && search.trim() === '' && !typeFilter && !phaseFilter
      ? '' // should never happen with all filters empty
      : '—'}
  </td>
</tr>
```

Simpler: just render a single centered `—` in a full-width cell when `filtered.length === 0`. No localized empty-state message needed.

### Table structure (unchanged from D0.3d)

The `<colgroup>` widths, header classes, `even:bg-bg2`, `overflow-x-auto`, `min-w-[960px]` — all preserved from D0.3d. The only change is the rows come from `filtered` instead of the full `connections` array.

### React key for rows

`Connection` has no `id` field (confirmed D0.3d). Use a composite: `${conn.from}-${conn.to}-${conn.type}`. If duplicates exist (same from+to+type), append index: `${conn.from}-${conn.to}-${conn.type}-${i}`.

## 7. Edge cases

- **`Connection` has no `id` field:** Use composite React key `${conn.from}-${conn.to}-${conn.type}`. If not unique (shouldn't happen but defend), append `-${i}`.
- **`conn.proto` is empty string or falsy:** `conn.proto || '—'` renders `—` in cell. Search on proto: `conn.proto ? conn.proto.toLowerCase().includes(q) : false` — never crashes on empty.
- **Phase dropdown shows all 8 phases including `ext`:** Some phases may have 0 connections (e.g., `ext` phase might not appear in EAIP connections). Selecting such a phase shows "0 connections" — correct, not an error.
- **`useMemo` dependency array:** Must include `connections`, `search`, `typeFilter`, `phaseFilter`. The `connections` prop is a static `as const` array — its reference never changes during the component's lifetime. Including it anyway is correct.
- **Phase option labels:** Use `lang === 'tr' ? p.labelTr : p.labelEn` — same pattern as phase badges in the table rows.
- **`select` element styling in dark theme:** Native `<select>` on macOS/Windows has OS-specific styling. Add `appearance-none` and a custom chevron via `bg-[url(...)]` if native select looks bad — or accept native styling for V0 (acceptable for internal tool). AG decides based on visual check and reports choice.
