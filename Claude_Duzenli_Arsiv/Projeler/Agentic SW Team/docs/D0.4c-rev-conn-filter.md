## 3. Context

### Difference 1 — Group filter (not phase)

```tsx
<select value={groupFilter} onChange={e => setGroupFilter(e.target.value)} aria-label={strings.allgr}>
  <option value="">{strings.allgr}</option>
  {groups.map(g => (
    <option key={g.id} value={g.id}>
      {lang === 'tr' ? g.labelTr : g.labelEn}
    </option>
  ))}
</select>
```

State: `const [groupFilter, setGroupFilter] = useState('')`.
Filter: `if (groupFilter && conn.group !== groupFilter) return false;`

### Difference 2 — Bilingual purpose search

`conn.purpose` doesn't exist — the fields are `conn.purposeEn` and `conn.purposeTr`. In the filter logic, search both:

```ts
if (search.trim()) {
  const q = search.toLowerCase();
  return (
    conn.from.toLowerCase().includes(q) ||
    conn.to.toLowerCase().includes(q) ||
    conn.purposeEn.toLowerCase().includes(q) ||
    conn.purposeTr.toLowerCase().includes(q) ||
    (conn.proto ? conn.proto.toLowerCase().includes(q) : false)
  );
}
```

Searching both language variants means a TR-language search term finds connections even when displayed in EN mode.

### Difference 3 — Purpose cell rendering

The purpose `<td>` renders the active language:
```tsx
<td className="py-3 px-3 text-sm text-text2">
  {lang === 'tr' ? conn.purposeTr : conn.purposeEn}
</td>
```

## 7. Edge cases

- **`conn.purposeTr` empty string:** Some connections may have `purposeTr: ''`. In search: `conn.purposeTr.toLowerCase().includes(q)` returns false for non-empty query — correct (empty TR is not a match). In purpose cell: `lang === 'tr' ? conn.purposeTr : conn.purposeEn` renders empty string; add fallback: `(lang === 'tr' && conn.purposeTr) ? conn.purposeTr : conn.purposeEn`.
- **All 5 groups exist in `REV_CONNECTIONS`:** From D0.3g confirmation. No group results in empty filter state.
- **React key uniqueness:** Rev connection pairs may be less unique than EAIP (smaller dataset, more internal connections). If `${conn.from}-${conn.to}-${conn.type}` has duplicates, append `-${i}`.
