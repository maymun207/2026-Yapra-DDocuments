## 1. Goal

- A `TR` / `EN` toggle button is visible in the site header across all 8 routes.

## 3. Context

### Why cookie, not URL searchParams

URL-based lang (`/?lang=tr`) would require every `<Link>` across the app to carry the query param — compounding complexity as routes render. A `lang` cookie is:
- Server-readable on every request via `next/headers` `cookies()` — no prop drilling from layout
- Persists across route navigation automatically — zero change to existing nav links
- Writable from a single client component via `document.cookie` + `router.refresh()`
- Not sensitive data — no `HttpOnly`, no `Secure` requirement

This is the correct choice for a single-domain internal tool. Do not suggest alternatives.

### The one-line change design

D0.3b deliberately hardcoded `const t = STRINGS.en.big` in each Big Picture component with the note that D0.3b.1 makes this "a one-line change." The change is:

```ts
// Before (D0.3b):
const t = STRINGS.en.big;

// After (D0.3b.1):
const t = STRINGS[lang].big;  // lang comes from props
```

Each component gains `{ lang }: { lang: Lang }` as its prop. `app/page.tsx` reads lang once, passes it down. This is the full extent of the Big Picture component changes.

### What stays untouched

The 7 placeholder route files (`/eaip/architecture`, `/eaip/connectivity`, `/eaip/schedule`, `/revolutionize/architecture`, `/revolutionize/connectivity`, `/revolutionize/schedule`, `/bridge`) are NOT modified. They will show the toggle button (because it's in the header — shared chrome), but their content stays EN-only placeholder until each route is rendered in a future stage.

## 4. Detailed task

### Step 1 — Create `app/_lib/lang.ts`

```ts
// app/_lib/lang.ts
import { cookies } from 'next/headers';
import type { Lang } from '@/app/_data/types';

export async function getLang(): Promise<Lang> {
  const cookieStore = await cookies();
  const value = cookieStore.get('lang')?.value;
  return value === 'tr' ? 'tr' : 'en';
}
```

Note: In Next.js 15, `cookies()` returns a `Promise` — `await` is required. Default is `'en'` for any value other than `'tr'`.

### Step 2 — Create `app/_components/ui/LanguageToggle.tsx`

```tsx
'use client';
import { useRouter } from 'next/navigation';
import type { Lang } from '@/app/_data/types';

export default function LanguageToggle({ current }: { current: Lang }) {
  const router = useRouter();

  function toggle() {
    const next: Lang = current === 'en' ? 'tr' : 'en';
    document.cookie = `lang=${next};path=/;max-age=31536000;SameSite=Lax`;
    router.refresh();
  }

  return (
    <button
      onClick={toggle}
      aria-label={current === 'en' ? 'Switch to Turkish' : 'Switch to English'}
      className="border border-border rounded-md px-3 py-1 text-sm font-mono text-text2 hover:text-text hover:border-text3 transition-colors shrink-0"
    >
      {current === 'en' ? 'TR' : 'EN'}
    </button>
  );
}
```

The button shows the language you will switch **to** (not the current one). Font-mono matches the dark-theme technical idiom established in D0.2. No flags, no icons.

## 5. What NOT to build

- ❌ Do NOT use `next-intl`, `react-i18next`, or any i18n library. We have `STRINGS`.
- ❌ Do NOT use URL `searchParams` for language state (`?lang=tr`). Cookie approach only.
- ❌ Do NOT use `localStorage` — breaks server rendering.
- ❌ Do NOT use React context for language — requires `'use client'` context provider wrapping the layout, which infects all server components under it.
- ❌ Do NOT make `NavTabs.tsx` or `MobileMenu.tsx` language-aware. They render tab labels from `nav.ts` which is not language-keyed yet.
- ❌ Do NOT add `generateMetadata` with lang alternates — out of scope.
- ❌ Do NOT modify the 7 placeholder route files.
- ❌ Do NOT change anything in `app/_data/`.
- ❌ Do NOT add a `'use client'` directive to `Header.tsx`, `BigPictureHero.tsx`, `LoopDiagram.tsx`, `SubstrateBanner.tsx`, or `AdrLandingNote.tsx` — all remain server components.
- ❌ Do NOT show `EN | TR` split-button UI. Single button showing the inactive lang only.
- ❌ Do NOT add `HttpOnly` to the cookie — it must be writable by JS (`document.cookie`).
- ❌ Do NOT add `Secure` to the cookie — this is an internal tool, not a sensitive credential.

## 7. Style and idiom requirements

- The `ui/` subdirectory under `_components` is the right home for shared leaf-level client components (future: theme toggle, tooltip, etc.). `LanguageToggle` is the first resident.
- `getLang()` is the single choke point for lang resolution — all server components in the app will eventually call it or receive the result as a prop. Do not duplicate the cookie-read logic.
- Big Picture components store the lang slice locally: `const t = STRINGS[lang].big`. This pattern is intentional for the future TR work — each component's diff is a single line.
- No `style={}` attributes. No CSS modules. Tailwind utility classes only.
- TypeScript strict — no `any`, no loose `string` where `Lang` applies.

## 8. Edge cases

- **Cookie not present (first visit):** `getLang()` returns `'en'` — correct default. No error.
- **Cookie value is an unexpected string (e.g. `'de'`, `'EN'` with caps):** `getLang()` falls through the `=== 'tr'` check and returns `'en'`. No error.
- **`STRINGS.tr.big.note` also contains `<b>...</b>` markup:** AG must verify this before asserting the TR note renders correctly. If the TR version of `note` has different markup, `dangerouslySetInnerHTML` still applies — no change to `AdrLandingNote.tsx` logic.
- **`STRINGS.tr.big.substrateitems` separator:** v6 TR uses the same ` · ` separator as EN. Confirm before splitting. If separator differs in TR, `SubstrateBanner.tsx` must handle it — flag in the PR description.
- **Header layout with toggle on mobile (375px):** The hamburger trigger is at the right side of the header. The toggle button is added alongside it. At 375px, both must fit without crowding the wordmark. Use `gap-2` or `gap-3` between them. If the wordmark truncates, reduce the toggle button's padding (`px-2`) on mobile only.
- **`router.refresh()` and React transitions:** After `router.refresh()`, Next.js re-fetches server component output. The page will briefly show stale content. This is acceptable — no loading spinner needed. Do not add `useTransition` to mask the refresh.
- **Making Header async:** Next.js 15 supports async server components without restriction. The only concern is if Header is rendered in a Suspense boundary — it is not (it's in the root layout). Safe to make async.
