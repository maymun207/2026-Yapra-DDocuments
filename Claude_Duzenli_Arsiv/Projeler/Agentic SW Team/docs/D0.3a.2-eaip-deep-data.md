## 1. Goal

Populate the EAIP data layer with the full depth from v5. After D0.3a.2:

- `app/_data/eaip-components.ts` exports `EAIP_COMPONENTS: readonly Component[]` — exactly 67 components, all 10 fields per `Component` type from D0.3a.1.
- `app/_data/eaip-connections.ts` exports `EAIP_CONNECTIONS: readonly Connection[]` — ~100 connections with full `purpose` paragraphs and verbatim `proto` strings.
- `app/_data/eaip-plan.ts` exports `EAIP_PLAN` — the phase-by-phase task / outcome / hours data from v5's `PLAN_DATA` (or v6's `EPLAN` if more complete).
- `app/_data/eaip-gantt.ts` exports `EAIP_GANTT` — the timeline data for the EAIP schedule tab.

No render code. No new types. No translations. Just data conforming to the schemas locked in D0.3a.1.

### Field-fidelity rule (load-bearing)

v5's `COMPS` and `CONNECTIONS` are the deep source. Every field on every record transfers verbatim into the typed TS modules. No paraphrasing of `desc`, `notes`, `purpose`, or `deploy.note`. No "improvement" of config-key descriptions. Identifiers (`id`, `name`, `proto`, env var keys in `config[].k`) are code — never modified.

### Schema reminder (from D0.3a.1, do NOT redefine here)

```ts
// already exported from app/_data/types.ts:
Component { id, name, layer, lname, phase, badge, sub, desc, deploy, config, notes, affectsStages? }
Connection { from, to, type, proto, purpose, phase }
ConfigKey { k, v, n }
Deploy { image, install, helm?, note? }
```

### Bilingual stance

v5 source is EN-only. All prose fields (`desc`, `notes`, `deploy.note`, `config[].n`, `Connection.purpose`) extract EN-only into the TS modules. TR translation is a dedicated later stage with TR-native review. **Do not auto-translate any v5 prose.**

## 4. Detailed task

### `app/_data/eaip-components.ts`

Read `docs/_source/v5_ssot.html`, locate `const COMPS = [...]` block. Extract all 67 component objects verbatim into a typed array. Each entry conforms exactly to the `Component` interface from `./types`. Export as `EAIP_COMPONENTS: readonly Component[]`.

Order preservation: v5's declaration order is significant (groups components by layer L0→L9). Preserve that order — the EAIP Architecture tab in D0.4 will render layer-by-layer in this sequence.

### `app/_data/eaip-connections.ts`

Read v5's `const CONNECTIONS = [...]` block. Extract all connection objects verbatim. Each `from` and `to` value must match a `Component.id` from `eaip-components.ts` — referential integrity matters because D0.4 will use these IDs to filter inbound/outbound connections per component.

Export as `EAIP_CONNECTIONS: readonly Connection[]`.

### `app/_data/eaip-plan.ts`

Extract v5's `PLAN_DATA`. If v5's structure doesn't match a clean typed shape, define a `EaipPlan` interface in this file (NOT in `types.ts` — local type, EAIP-specific). Cross-reference v6's `EPLAN` only to fill gaps; if v5 and v6 disagree on a field value, **v5 wins** (depth source) and note the discrepancy in lessons.md.

### `app/_data/eaip-gantt.ts`

Extract v5's `TIMELINE`. Same local-type pattern: define `EaipGanttRow` (or similar) in this file. The gantt data is straightforward — phase rows with start/end month indices.

## 6. Acceptance criteria

- `npm run build` clean; `npx tsc --noEmit` exits 0.
- `EAIP_COMPONENTS.length === 67` (the canonical count from §2.1 of context_boostrapt_combo_prj.md).
- Every component has all required fields populated (`id`, `name`, `layer`, `lname`, `phase`, `badge`, `sub`, `desc`, `deploy.image`, `deploy.install`, `config` is an array, `notes`). `affectsStages` is the only optional field; leave undefined.
- `EAIP_COMPONENTS` ids are unique (no two components share an `id`).
- Every layer in `LAYERS` (from D0.3a.1) has ≥ 1 component (no orphan layer).
- Every phase in `PHASES` (from D0.3a.1) has ≥ 1 component (no orphan phase).
- `EAIP_CONNECTIONS.length` matches the v5 source count (expected ~100; AG reports the exact number in lessons.md).
- Every `Connection.from` and `Connection.to` resolves to a `Component.id` in `EAIP_COMPONENTS` (no dangling references).
- Every `Connection.type` is a member of the `ConnTypeId` union from D0.3a.1.
- Per-field spot-check assertion: a smoke test (inline in a test file or one-off script AG runs) asserts:
  - `EAIP_COMPONENTS.find(c => c.id === 'qdrant').deploy.image === 'qdrant/qdrant:v1.9'`
  - `EAIP_COMPONENTS.find(c => c.id === 'whatsapp').layer === 'L0'`
  - `EAIP_CONNECTIONS.some(c => c.from === 'whatsapp' && c.to === 'gateway' && c.type === 'WEBHOOK')`
- `EAIP_PLAN` and `EAIP_GANTT` have non-empty values for at least the `core`, `cwf1`, and `ins` phases.

## 7. Style and idiom requirements

- `as const` on every top-level data array.
- Imports: `import type { Component, Connection } from './types'`.
- `kebab-case` filenames; `SCREAMING_SNAKE_CASE` for top-level data constants (`EAIP_COMPONENTS`, `EAIP_CONNECTIONS`, `EAIP_PLAN`, `EAIP_GANTT`).
- Multi-line object literals: one field per line for `Component` and `Connection` records — these will be diffed and reviewed individually.
- No `any`. If TS strict complains about a v5 field shape, narrow the type in `types.ts` (and surface the change in lessons.md) — do not cast.
- Preserve Unicode escapes (`\u2019` etc.) verbatim from source.

## 8. Edge cases

- **Components with missing optional fields in v5:** some components may not have `deploy.helm` or `deploy.note`. The `Deploy` type marks these `?` — omit them entirely from the record (do not set to `null` or empty string).
- **`config[]` may be empty for some components:** preserve as `config: []`, do not omit the field.
- **`phase` values that don't match `PhaseId` union:** if v5 has a phase value not in `'core'|'wa'|'gu'|'cwf1'|'ins'|'cwf2'|'fin'`, flag it in lessons.md and do not fabricate. Possible cause: v5 used different ids that need mapping (e.g., `'platform'` → `'core'`).
- **`type` values that don't match `ConnTypeId` union:** same rule — flag, don't fabricate.
- **HTML in v5 prose fields:** v5 `purpose` paragraphs may contain inline tags. Preserve verbatim — D0.5's connectivity render will handle them.
- **Very long `purpose` strings:** some connections have multi-sentence purpose paragraphs (50+ words). Keep as a single string field; do not split.
- **Components with the same `name` but different `id`:** allowed — names can repeat (e.g., a component named "Postgres" in two layers). `id` is the unique key.
