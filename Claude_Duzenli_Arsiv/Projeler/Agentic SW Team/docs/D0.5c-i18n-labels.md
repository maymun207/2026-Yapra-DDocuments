### Pattern for wiring STRINGS to `'use client'` components

`LayerGridClient` and `RevSystemGridClient` are `'use client'` — they cannot import STRINGS at runtime (Pattern #25). The established solution: server page computes the strings from STRINGS and passes them as props.

**`app/eaip/architecture/page.tsx`** — add:

```tsx
import { STRINGS } from '@/app/_data/i18n';
// ...
const panelStrings = {
  description: STRINGS[lang].ui.description,
  notes:       STRINGS[lang].ui.notes,
  inbound:     STRINGS[lang].ui.inbound,
  outbound:    STRINGS[lang].ui.outbound,
};
// Pass to LayerGridClient:
<LayerGridClient ... panelStrings={panelStrings} />
```

**`app/revolutionize/architecture/page.tsx`** — add:

```tsx
import { STRINGS } from '@/app/_data/i18n';
// ...
const panelStrings = {
  connections: STRINGS[lang].ui.connections,
  inbound:     STRINGS[lang].ui.inbound,
  outbound:    STRINGS[lang].ui.outbound,
  system:      STRINGS[lang].ui.system,
};
// Pass to RevSystemGridClient:
<RevSystemGridClient ... panelStrings={panelStrings} />
```

**`LayerGridClient.tsx`** — add `panelStrings` to props interface, replace all 4 hardcoded EN strings with `panelStrings.X`. Use `import type` for the prop shape — do not import STRINGS.

**`RevSystemGridClient.tsx`** — same pattern: add `panelStrings` to props interface, replace hardcoded strings.

## 7. Edge cases

- **`panelStrings` prop type inline vs `StringsForLang['ui']`:** Either approach is valid. Using `import type { StringsForLang } from '@/app/_data/i18n'` and typing as `panelStrings: StringsForLang['ui']` is cleanest — type-only import, no runtime cost. Or define inline `{ description: string; notes: string; ... }`. Report choice in PR.
- **`rplan.lg1/2/3` → `bound` mapping must be verified in Step 0.** Expected: `lg1`=impl (green), `lg2`=mix (blue), `lg3`=cal (amber/hatched). If Step 0 reveals a different mapping, use the actual mapping, not the expected one.
- **EaipGanttChart has no hardcoded strings:** If Step 0 confirms zero hardcoded EN-only strings (EAIP gantt may only use phase colors and PHASES data which are already language-neutral), skip Step 7 and explicitly document "EaipGanttChart: no hardcoded UI strings found — no change needed" in PR body.
- **`LayerGridClient` "Connections" heading:** D0.4d may not have a "Connections" heading — it may use "Outbound" and "Inbound" directly as section labels without a parent "Connections" header. Step 0 confirms. Only add `connections` to LayerGridClient's props if Step 0 finds it hardcoded.
