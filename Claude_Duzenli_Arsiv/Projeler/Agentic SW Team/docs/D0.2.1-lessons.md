## § Prompt-author retrospective (Claude)

**What the D0.2.1 prompt got right:**
- Patch scope held. AG touched exactly the 5 files in §10 modified-files list, no scope creep, no new files. The XS sizing held.
- §9 edge case on container max-width turned out to be load-bearing — `max-w-screen-2xl` widening was applied during execution. Without that note, the full-label tier might have cramped inside an existing `max-w-7xl` constraint.
- The `2xl:inline hidden` / `2xl:hidden inline` dual-span idiom for label switching is clean. Worth canonicalizing in the Pattern Library.
- "Delete the failed scroll hack" was treated as a first-class step rather than a footnote. AG removed the rule cleanly.

**What the D0.2.1 prompt could have done better:**
- The §13 lessons template asks for AG self-graded post-mortem questions (`what I did well / missed / got wrong / surprises`). AG produced a delivery summary instead — useful, but not the self-graded reflection the template structurally requests. The template needs to explicitly instruct AG: *"After execution, before committing, write your self-graded post-mortem against these four questions."* Otherwise we get delivery summaries that look like lessons but skip the reflection step.
- The "no horizontal scrollbar anywhere" acceptance criterion in §1 and §6 worked — but it's a *negative* assertion. AG verified it by running endpoint audits and stating no scrollbar appeared. A stronger acceptance criterion would prescribe a positive verification mechanism (e.g., "DevTools console: `getComputedStyle(document.querySelector('header')).overflowX` returns `visible`, not `auto` or `scroll`"). Going forward, layout-related acceptance criteria should include at least one positive computed-style assertion alongside the visual checks.

**Pattern Library entries added by this stage:**
- **#7:** Three-tier responsive label idiom — `label` + `shortLabel` in nav array, swap via `2xl:` Tailwind utility, hamburger below `lg:`. Reusable for any nav with > 6 items at average label length > 18 chars.
- **#8:** Patch stages are appropriately XS-sized when scope is bounded to N existing files + zero new files. D0.2.1 took 5–8 min; D0.1 took 2 min; D0.2 took 10 min. Pattern: file count is a reasonable size proxy.
- **#9:** Acceptance criteria for layout work must specify positive computed-style assertions, not just visual checks and negative assertions ("no scrollbar"). Add to D0.X template defaults.
- **#10:** Model recommendation in §12 is honored when operator manually sets the model in AG UI. The model_recommended/model_used split in lessons.md captures the substitution log when they diverge.

**Updates to D0.X template going forward (effective from D0.3):**
- §13 lessons template gains explicit AG instruction: *"Before commit, write your self-graded post-mortem against (a) what I did well, (b) what I missed or got wrong — at minimum one observation, (c) surprises, (d) prompt weaknesses identified."*
- §6 acceptance criteria for any UI/layout/CSS stage must include ≥ 1 positive computed-style assertion in addition to visual checks.

Reasoning: v6 SSoT source is 1471 lines with ~10 data dicts; extracting them cleanly to typed TS modules under `app/_data/` is its own concern, independent of the rendering surface. Single stage would push into L territory and the lessons.md attribution would be muddier (was the bug in data shape or render?).
