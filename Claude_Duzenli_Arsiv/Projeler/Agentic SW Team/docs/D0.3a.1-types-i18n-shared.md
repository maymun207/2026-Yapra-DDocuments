## 3. Context

### Why types first

D0.4 (EAIP Architecture tab with click-to-detail panel) and D0.5–D0.9 all consume the same data contract. Defining types in their own stage means:
- TS strict mode catches any v5→v6 schema drift during D0.3a.2/.3 extraction
- D0.4 can be designed against the type contract before data is fully populated (parallel work possible)
- Pattern Library entry: "data extraction stages always start with types"

## 4. Detailed task

### Step 1 — `app/_data/types.ts`

Define schemas verbatim. These are load-bearing for D0.3a.2 onward:

```ts
// app/_data/types.ts

export type LayerId = 'L0' | 'L1' | 'L2' | 'L3' | 'L4' | 'L5' | 'L6' | 'L7' | 'L8' | 'L9';
export type PhaseId = 'core' | 'wa' | 'gu' | 'cwf1' | 'ins' | 'cwf2' | 'fin';
export type ConnTypeId =
  | 'REST' | 'MCP' | 'WS' | 'KAFKA' | 'CDC' | 'OIDC' | 'GRPC' | 'S3'
  | 'WEBHOOK' | 'PSQL' | 'SDK' | 'GRAPH' | 'JDBC' | 'OTEL' | 'SMB' | 'HTTP';
export type Lang = 'en' | 'tr';

export interface Layer {
  id: LayerId;
  name: string;          // EN; structural label
  tag: string;           // EN; doctrine note (can be empty string)
  adapt: boolean;        // is this an adapter port (swappable layer)?
}

export interface Phase {
  id: PhaseId;
  color: string;         // hex
  labelEn: string;
  labelTr: string;
}

export interface ConnType {
  id: ConnTypeId;
  color: string;         // hex
  descEn: string;
  descTr: string;
}

export interface ConfigKey {
  k: string;             // env var name
  v: string;             // default / sample value
  n: string;             // description (EN only in v5; bilingual TR added in later stage)
}

export interface Deploy {
  image: string;
  install: string;
  helm?: string;
  note?: string;
}

export interface Component {
  id: string;            // unique identifier from v5 (e.g., 'whatsapp', 'qdrant')
  name: string;
  layer: LayerId;
  lname: string;         // layer display name
  phase: PhaseId;
  badge: string;         // 'P0', 'WA', 'GU1', 'CWF1', 'INS', etc.
  sub: string;           // one-line description
  desc: string;          // full description (EN)
  deploy: Deploy;
  config: ConfigKey[];
  notes: string;         // operational notes (EN)
  affectsStages?: string[];   // populated in later stage when stage-to-component mapping lands
}

export interface Connection {
  from: string;          // Component.id
  to: string;            // Component.id
  type: ConnTypeId;
  proto: string;         // full protocol string (verbatim from v5)
  purpose: string;       // EN; purpose paragraph
  phase: PhaseId;
}
```

## 8. Style and idiom requirements

- TypeScript strict — zero `any`, prefer `unknown` + narrowing
- Use `as const` on all top-level data arrays so types narrow to literal unions where appropriate
- File naming: `kebab-case` for file names (matches D0.2 convention), `PascalCase` for type names, `SCREAMING_SNAKE_CASE` for top-level data constants (`LAYERS`, `PHASES`, `CONN_TYPES`, `STRINGS`)
- Imports via `@/*` alias for cross-module imports (e.g., `import type { Layer } from '@/app/_data/types'`)
- Within `app/_data/*.ts`, use relative imports (`./types`) to keep the data layer self-contained
- No runtime validation libraries — TypeScript strict + acceptance assertions are sufficient at this scale

## 9. Edge cases to handle explicitly

- **Unicode escapes in v6:** v6 uses `\u2019` for typographic apostrophes and other escape sequences for Turkish characters. Preserve them verbatim — do NOT convert to literal characters. TypeScript handles both forms identically at runtime, but the verbatim form preserves diff-traceability against v6.
- **HTML tags in v6 strings:** several strings in `T.en.eplan.risk` and similar contain inline `<b style="color:var(--red)">...</b>` markup. These are intentional — preserve verbatim. Rendering layer (D0.3b+) will use `dangerouslySetInnerHTML` for these specific fields (with a strict allowlist).
- **v6 `LAYERS` may lack the `adapt` field:** v5 has `adapt: true/false`; v6 may have omitted it. If v6 doesn't include `adapt`, set it to `false` for all layers EXCEPT L0/L2/L3/L4/L6 (which v5 marks `true`). Document this choice in lessons.md retrospective.
- **`CTYPES` count discrepancy:** v6 line 277 includes 16 connection types per inspection. If the actual count differs, update the `ConnTypeId` union in `types.ts` to match exactly. Do NOT add types that don't exist in v6.
- **`EPH` order is significant:** the `PHASES` array order drives Gantt rendering in later stages. Preserve v6's declaration order: `core, wa, gu, cwf1, ins, cwf2, fin`.
- **Empty `tag` strings in LAYERS:** v6 has some layers with `tag:''` (empty). Preserve as empty string, do NOT replace with `undefined` or omit the field.
