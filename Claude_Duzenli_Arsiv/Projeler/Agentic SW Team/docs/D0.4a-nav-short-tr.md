## 1. Goal

Short tab labels at the 1024–1535px viewport tier switch to Turkish when `lang=tr`. After D0.4a:

- At ≥1536px: full TR tab labels (already live from D0.3c).
- At 1024–1535px: TR short labels for the 7 tabs that have a `tabKey`. Bridge & Charter stays EN (no `tabKey`, no TR short form).
- At <1024px (mobile menu): full TR labels already work from D0.3c — mobile menu unaffected.
- Elsewhere unchanged. No new routes, no data changes, no `'use client'` additions.

## 2. Prerequisites

- D0.3i merged at `0112649`. All 8 routes live.
- `app/_lib/nav.ts` has `NavItem` with `label`, `shortLabel`, `href`, `tabKey?: TabKey`.
- `app/_components/NavTabs.tsx` and `MobileMenu.tsx` are `'use client'`, receive `tabLabels: StringsForLang['tabs']` prop from Header. **Neither currently receives `lang` as a prop.**
- `app/_components/Header.tsx` is async, has `lang: Lang` from `getLang()`, passes `tabLabels` to NavTabs and MobileMenu.
- TypeScript strict passing. `npm run build` clean.

## 3. Context

### The gap this fills

D0.3c deliberately deferred TR short labels:
> "Short labels (1024–1535px tier) stay EN always — no short-form TR added this stage. Adding TR short labels requires either extending `STRINGS` (locked) or adding `shortLabelTr` to nav.ts (out of scope)."

D0.4a closes that gap. STRINGS remains locked. `shortLabelTr?: string` is added to `NavItem` in nav.ts.

### Implementation

Three changes, all small:

**1. `app/_lib/nav.ts`** — add `shortLabelTr?: string` to `NavItem`. Populate for 7 tabs (see Step 0). Bridge & Charter gets no `shortLabelTr` — intentional.

**2. `app/_components/Header.tsx`** — add `lang={lang}` to the `<NavTabs>` and `<MobileMenu>` render calls. Header already has `lang` from `getLang()`.

**3. `app/_components/NavTabs.tsx`** and **`app/_components/MobileMenu.tsx`** — add `lang: Lang` to props type. Update short-label selection:

```tsx
// Current (EN only):
<span className="2xl:hidden inline">{item.shortLabel}</span>

// After D0.4a (lang-aware):
<span className="2xl:hidden inline">
  {lang === 'tr' ? (item.shortLabelTr ?? item.shortLabel) : item.shortLabel}
</span>
```

`item.shortLabelTr ?? item.shortLabel` — if no TR short label is set, fall back to EN. Bridge & Charter falls back correctly.

MobileMenu does NOT have a short-label tier (it shows full labels). The `lang` prop is added to MobileMenu for completeness and consistency, but no label logic changes there — MobileMenu can ignore `shortLabelTr`.

### Step 0 — read TR full labels, propose short forms

Before writing any code, AG reads `STRINGS.tr.tabs.*` actual values from `app/_data/i18n.ts` and proposes a `shortLabelTr` for each of the 7 keyed tabs.

**Short-label style constraints:**
- ≤ 3 words
- Match the EN abbreviation pattern (EN short labels drop "ize" suffixes, abbreviate to "Arch"/"Conn"/"Plan" etc.)
- Grammatically natural in Turkish — do not mechanically translate the EN short form
- List all 7 proposed TR short labels in the PR body — Maymun's linguistic review is the gate

Expected pattern (illustrative — AG fills actual TR labels from STRINGS):

| Big Picture | `[current EN short]` | TR equivalent, ≤ 3 words |

AG reads `STRINGS.tr.tabs.*` and derives these — do NOT use the English forms above as-is. Report actual TR full label + proposed TR short label for each row.
