## 1. Goal

Close two referential integrity gaps surfaced by D0.3a.2's extraction:

1. **`phase: 'ext'` is in the `PhaseId` type union but has no `Phase` object** in `phases.ts`. 10 external-adapter components (L8/L9: MariaDB, IoT-Ignite, ARMES, Exchange, ARU/KARU, SMB Shares, SAP, SharePoint, Salesforce, Netaş Cloud) reference a phase that lacks rendering metadata.

2. **4 connections reference sub-component IDs that have no `Component` entry:** `prometheus` (sub of `grafana`), `redpanda` (sub of `debezium`), `falkordb` (sub of `graphiti`). The connections are correct per v5 (metrics flow to the binary, not the parent package), but D0.4's click-to-detail panel will break on these dangling references.

After this patch:
- `PHASES.length === 8` with the new `ext` entry rendering as `External` / `Harici`.
- `EAIP_COMPONENTS.length === 70` (67 originals + 3 sub-component stubs).
- All 100 `EAIP_CONNECTIONS` resolve `from` and `to` to a real `Component.id`.
- `Component` interface gains an optional `subOf?: string` field to model the parent-child relationship explicitly.

## 2. Prerequisites

- D0.3a.2 merged on `main`. `EAIP_COMPONENTS` count = 67. `EAIP_CONNECTIONS` count = 100. The 4 dangling targets (`prometheus`, `redpanda`, `falkordb`) and the orphan `phase: 'ext'` are present.
- TypeScript strict still passing on `main`.

## 3. Context

### Why these gaps exist

v5's data model treats a few packages (`grafana`, `debezium`, `graphiti`) as primary components but routes connections to their internal binaries (`prometheus`, `redpanda`, `falkordb`) when the wiring is to the binary specifically. The `phase: 'ext'` value tags the 10 L8/L9 external systems — sovereign-adjacent but operated outside the cluster.

D0.3a.2 correctly transferred all of this verbatim. D0.3a.1's schema (`PhaseId` union, no `subOf` field) didn't anticipate either pattern. This patch closes both gaps without changing extracted data fidelity.

### Schema additions (the only type changes in this patch)

```ts
// app/_data/types.ts — modifications:

// PhaseId already gained 'ext' in D0.3a.2 — no change here, just confirm it's present
export type PhaseId = 'core' | 'wa' | 'gu' | 'cwf1' | 'ins' | 'cwf2' | 'fin' | 'ext';

// Component gains one optional field:
export interface Component {
  id: string;
  name: string;
  layer: LayerId;
  lname: string;
  phase: PhaseId;
  badge: string;
  sub: string;
  desc: string;
  deploy: Deploy;
  config: ConfigKey[];
  notes: string;
  affectsStages?: string[];
  subOf?: string;          // NEW — parent Component.id when this is a sub-component
}
```

## 7. Style and idiom requirements

- `as const` preserved on `PHASES` and `EAIP_COMPONENTS`.
- Sub-stub records use the same per-field-on-its-own-line style as the original 67 — they will be diffed individually.
- `subOf` is optional on the type and omitted on the 67 originals (not set to `undefined` or empty string — simply absent from the record).
- No `any`, no inline casts.

## 8. Edge cases

- **If the parent component's `badge` is something unique to its phase (e.g., `CWF1`, `INS`), the stub inherits that badge verbatim.** Don't introduce a `SUB` badge — sub-relationship is conveyed by `subOf`, not by a badge variant.
- **The 3 stub `deploy.image` and `deploy.install` values are `'—'` (em-dash) intentionally.** They're not deployable on their own; D0.4's render layer will display this as "(bundled with [parent])" without trying to make it a clickable image link.
- **`config: []` for all 3 stubs.** They inherit configuration from their parent's Helm chart; there are no independently-tunable env vars.
- **If the operator review finds a 5th dangling target the AG self-report missed**, surface it in lessons.md and add it as a 4th stub in a follow-up patch — do not silently add it in this patch's scope.
