1 · Developer connection topology

1 · Geliştirici bağlantı topolojisi

The rule of this picture is one sentence: each workstation has four connections, but exactly one connection point for model calls — the gateway wrapper. Developers do not talk to each other directly; coordination flows through GitHub (PRs + shared stage prompts). Git is the collaboration bus.

Bu resmin kuralı tek cümle: her workstation'ın dört bağlantısı var, ama model çağrıları için tam olarak tek bağlantı noktası — gateway wrapper. Geliştiriciler birbirleriyle doğrudan konuşmaz; koordinasyon GitHub üzerinden akar (PR'lar + ortak stage prompt'ları). Git, collaboration bus'tır.

Which IDE each developer uses

Her geliştirici hangi IDE'yi kullanır

Production path is VS Code with an agent extension that supports a custom OpenAI-compatible base URL — Roo Code (recommended, native LiteLLM provider with model auto-discovery), Cline, or Continue. Each engineer points the extension at the gateway wrapper and authenticates with their own virtual key.

Production yolu, custom OpenAI-uyumlu base URL'i destekleyen agent extension'lı VS Code'dur — Roo Code (önerilen, native LiteLLM provider + model auto-discovery), Cline veya Continue. Her mühendis extension'ı gateway wrapper'a yönlendirir ve kendi virtual key'iyle auth olur.

Why AG cannot sit behind the gateway

AG neden gateway'in arkasına geçemez

Antigravity does not expose a custom-provider / BYOK hook for swapping its in-editor agent model. A raw Anthropic key entered in AG goes straight to Anthropic, bypassing the gateway — so per-agent attribution, per-minute burst limits, canonical telemetry and prefix-cache emission are all lost. Reverse-proxy hacks exist but are reverse-engineered and prohibited by Google. Therefore AG stays a swappable executor for git / filesystem / deploy, while budget-sensitive model work routes through VS Code + gateway.

Antigravity, in-editor agent modelini değiştirmek için custom-provider / BYOK hook'u sunmaz. AG'ye girilen ham Anthropic key doğrudan Anthropic'e gider, gateway'i atlar — böylece per-agent attribution, per-minute burst limit, canonical telemetry ve prefix-cache emission'ın hepsi kaybolur. Reverse-proxy hack'leri var ama reverse-engineered ve Google tarafından yasaklı. Bu yüzden AG, git / filesystem / deploy için swappable executor olarak kalır; budget-hassas model işi VS Code + gateway'den geçer.

4 · LLM gateway — LiteLLM + wrapper

4 · LLM gateway — LiteLLM + wrapper

Per ADR-001 the gateway is LiteLLM (the OSS proxy) wrapped by a thin (~500 LOC) project layer. Agents never import LiteLLM directly — they call the wrapper. The wrapper holds the four capabilities LiteLLM does not cover: agent-aware cost attribution, per-minute token-burst limits, prefix-cache hit emission to the telemetry pipeline, and Living-Knowledge-driven routing.

ADR-001'e göre gateway, ince (~500 LOC) bir proje katmanıyla sarılmış LiteLLM'dir (OSS proxy). Agent'lar LiteLLM'i doğrudan import etmez — wrapper'ı çağırır. Wrapper, LiteLLM'in kapsamadığı dört yeteneği tutar: agent-aware cost attribution, per-minute token-burst limit, telemetry pipeline'a prefix-cache hit emission, ve Living-Knowledge tabanlı routing.

Single shared gateway, but one virtual key per developer. A single gateway endpoint is correct (central attribution, budget, telemetry only work with one shared gateway). But every developer/agent gets a distinct virtual key with its own budget — sharing one key would destroy attribution. Production IDEs connect to the wrapper (which must expose /v1/chat/completions and /v1/model/info), not raw LiteLLM, or the four custom capabilities are bypassed. The endpoint is a network-reachable, auth-guarded address — never localhost.

Tek paylaşılan gateway, ama geliştirici başına bir virtual key. Tek gateway endpoint'i doğrudur (central attribution, budget, telemetry yalnızca tek paylaşılan gateway ile çalışır). Ama her geliştirici/agent kendi budget'iyle ayrı bir virtual key alır — tek key paylaşmak attribution'ı yok eder. Production IDE'leri raw LiteLLM'e değil wrapper'a bağlanır (wrapper /v1/chat/completions ve /v1/model/info expose etmeli), yoksa dört custom capability atlanır. Endpoint ağdan erişilebilir, auth-korumalı bir adrestir — asla localhost değil.

5 · MCP tool servers

5 · MCP tool serverlar

Per ADR-002 the external tool surface is MCP, with a per-agent capability allowlist enforced at server boot. The filesystem server (1.7.4) ships first as the calibration stage, then web/docs, git/github, and sandbox.
