Agent Control Plane · Blueprint

The Electron Microscope A stage-by-stage lab for observing, tweaking, and replaying a single agent — before it becomes a product.

Five SOTA references agree on what an agent's pipeline is (14 stages, raw query → LLM → rendered answer). None of them describe the layer that turns a pipeline into a lab: the control plane that lets an engineer see each stage, change its input, and re-run it — and drop a stub where a stage is missing. That layer is the differentiator. This blueprint maps the canonical 14 stages against what CWF can do at each one today, and names the gaps by plan, not by accident. Scope: single-agent optimization bench. Multi-agent orchestration is deliberately out of scope at this stage — master one agent's behavior first.

02 Where the references diverge — and where CWF takes a stand

Union is easy; the separation points are where the design lives. Two of these are not gaps to fill later — they are CWF's identity, and the blueprint records them as chosen, not missing.

No vector in the knowledge core DIVERGENT · stage 05

All five references assume RAG = vector search (top-k, HyDE, re-rank, Graph-RAG). CWF's deterministic core bans it: the critical slice is always-injected typed data, never lossy near-neighbor retrieval that could confuse IKINCILUST with IKINCILALT and corrupt a fact. pgvector stays a gated slot for a future advisory Layer-2 corpus only.

No LLM-as-judge in verification DIVERGENT · stage 11

The references converge on a critic / judge model (Reflexion, LLM-as-Judge, guard models). CWF bans it for grounding and trust: a judge can hallucinate its own verdict. Verification is deterministic code — empty≠zero, count-integrity, scope-authority — a function of provenance, not a model's opinion.

Planning is implicit — for now DEFERRED → LangGraph

Docs make an explicit hierarchical Planner / Task-Graph / DAG a first-class stage. CWF plans implicitly inside the stepCountIs tool loop today. An explicit planner is deferred to the LangGraph bridge (Shape B: TS core stays an MCP service, Python orchestrates, governance untouched) — a plan, with an address.

Intent, memory, skills — reduced by design PARTIAL / GAP

Intent: a keyword router feeds tool-selection only — no separate intent LLM (single-domain agent; a separate model adds latency + an error surface). Memory: short-term window ✓; learned user memory is a deliberate gap. Skills: SKILL.md serves the author lane, not a runtime skill layer.

What the market already sells

Observability (read-only): Langfuse, LangSmith, Phoenix, Braintrust, Weave — trace trees, spans, tokens. You watch a run; you can't re-run a stage.

Prompt replay (one stage): LangSmith Playground, Langfuse, PromptLayer — edit the prompt and re-run. Only the prompt stage; not tool-select, retrieval, or grounding.

Graph studios (framework-bound): LangGraph Studio — breakpoints, edit-state, time-travel — but only for graphs built its way.

What we build — and why it's ours

Buy the telescope, build the microscope stage. Observability is a solved import (Langfuse via F-obs). The differentiator is the layer on top: domain-aware tweak + replay + stub across every stage — including the ones no generic tool understands (deterministic grounding, scope-authority, governed knowledge, empty≠zero).

A competitor watching a dashboard and editing a prompt cannot see, let alone replay, our knowledge-floor or scope-authority stages. Their tool doesn't know our domain. Ours will.

05 How the gaps close — the build order

The control plane is built in the order that makes each next layer verifiable. Observe before tweak; tweak before replay; replay before extensibility.

1

Observe backbone — unpark F-obs

Self-hosted Langfuse + OTel span tree. Fills the observe gaps in one move: the final per-request prompt (stage 08), per-step reasoning (stages 03/10), and a single trace id (folds the TD-10 session_id reconciliation in). Blocked only on host placement (OA-8).

2

Tweak expansion — widen the GOV-4 lab overlay

Extend the existing session-only, read-only overlay from 5 stages to every tweakable one — always server-authorized, never touching governed state. The safety model already exists; this is coverage.

3

Replay — the genuinely new build

Capture a request's stage inputs; re-run one stage with a tweak; diff the output against the original. This is the empty column and the heart of the microscope — nothing off-the-shelf does it for our stages.

4

Stub & extensibility — add a layer

A pluggable stage interface: drop a stub where a stage is missing, or let an engineer write a small JS/Python transform, run it in isolation, and see its effect through observe+replay.

·

Out of scope, on purpose — multi-agent orchestration

Not now. The bench optimizes one agent to product quality first; orchestration is a later chapter, not this one.

Held for the next pass — the control plane needs a home. Observe and tweak surfaces today live in scattered logs and the admin/settings/telemetry pages. Those pages are the intended UI home for this control plane and are a known redesign target (the telemetry page in particular has acknowledged bugs and missing features). This blueprint deliberately stops at the capability map; the UI redesign that gives it a home is a separate, sequenced phase — flagged here so the two stay linked.
