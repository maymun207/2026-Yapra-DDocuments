Agent anatomy · where the canonical parts live

LLM interface

The model call seam

_lib/llm/gateway.ts — one streamChat → streamText call site (all providers, no per-provider path) + llm/config.ts (models, cost). Second, off-gateway LLM: the tool router (gemini-2.5-flash-lite via @google/genai) — a consolidation candidate.

tool interface

MCP adapter + meta-tools

executeMCPTool · connectMcp · discoverMcpTools (chat.ts) + scopeTools.ts + meta-tools resolve_time_range, aggregate_records, query_records, resultStore.ts. ARMES = flat tools; Superset = search/call gateway.

router / planner

Two layers

Pre-selection: filterToolsByMessage (keyword cache → router LLM on miss). True planning: the streamText multi-step loop itself — the model plans by choosing a tool each step, observing, repeating.

persona

Per-backend voice

Domain-pack personaText (armes / superset) + core identity, composed by the assembler. Not a free-text blob — it's a governed module.

system prompt

Composed, not hard-coded

prompt/assemble.ts = core modules (identity · safety · time · toolProtocol · grounding · outputFormat) + domain packs, assembled per active backend. → future Prompt Store (Langfuse).

memory · 3 kinds

Distinct, not one bag

Conversational: last-N conversationHistory + conversations/messages tables. Knowledge (governed, not learned): DbKnowledgeProvider over rule_kinds/domain_rules. Procedural (the only self-learning): tool_category_cache — router mappings, advisory.

guardrails

Deterministic, never the LLM

groundingCheck.ts (empty≠zero · scope-divergence) + trustRegistry.ts (authority ceiling) + envelope provenance. Code, not a model judge/score.

clock

Tools-of-record

networkTime.ts (NTP "now") + resolve_time_range (TZ-aware). The model is forbidden to compute epochs itself.

identity / authz

Server-trusted only

auth.ts (JWT verify) + RolesRepository (role + per-backend scopes) + resolveActiveBackends. No client-claimed role is trusted.

How many agents — the honest map

primary · the only true agent

Chat agentic loop

Gateway streamText with stepCountIs. Perceives (tool results) → plans (next tool) → acts → observes → repeats. One query = multiple provider round-trips (1 + 1 per tool result). Owns persona, system prompt, all MCP tools.

auxiliary · single-shot LLM

Tool router

routerSelectCategories — gemini-2.5-flash-lite, off-gateway, fires only on a tool_category_cache miss (non-Anthropic). A classifier, not a loop. Result is learned so next time it's skipped. Not a full agent.

NOT agents · deterministic services

Grounding · trust · time · gate

By design these are code, never an LLM: groundingCheck, trustRegistry, networkTime/resolve_time_range, the publish eval-gate, provenance. The correctness floor must not depend on a model.

◆ today: 1 agent + 1 auxiliary router LLM

The EAIP roadmap (LangGraph Shape-B) would later orchestrate multiple agents — but as of HEAD a8bd531 there is exactly one agentic loop plus one off-gateway classifier LLM. Everything else that "decides" is deterministic code.

◆ Q3 answer — who calls the MCP tool

The model decides which tool + args (it emits a tool-call request). Our Zone-2 process executes it via the registered execute closure inside this loop. Sequence per step: streamText → LLM [net] → tool-call request → our execute [in-process] → MCP backend [net] → result → back to LLM [net] → next step. Sequential awaits, one event-loop. The model never picks a Supabase table — those are read by our code at fixed steps; the model only picks external MCP tools.

◆ the model touches none of these

Every Supabase table above is read/written by our code at fixed steps — deterministic, never a model decision. The model's only "data choice" is which external MCP tool to call. rule_versions / rule_audit never appear in the chat path: they exist purely so governance is traceable.

governance invariant

The chat path (steps 1–30) only reads rule_kinds/domain_rules/backends and only at the published version. The admin lane is the sole writer, and the eval-gate (A2) is the single chokepoint — there is no other way to set published. This is why a poisoned rule can be drafted but never served.
