## §2 The owner's demand and the answer (the load-bearing arc)
The owner's core, repeated demand: **stop sending me to Vercel to rotate a daily token; finish the MCP screen once.** The honest diagnosis reversed an earlier "secret→env-only" dogma: the forbidden thing is a secret VALUE in the *world-distributed* global row (the panel GET + `mergeMcpServers` reach every user), NOT "a secret in Supabase." So the right answer is an **isolated, service-role-only store** (`mcp_secrets`) that never ships to a client — exactly the mainstream managed-secret pattern. MCP-SECRET-REF-1's `resolveAuthHeader` was the seam it plugged into (`apiKeyRef` = pointer #2 next to `apiKeyEnv`). Daily rotation became one UI Rotate. RULE 29 (the DONE contract, ultimately nine invariants) was written so the screen never reopens for another UI/UX pass.

## §3 Superset: the two-layer gap the marathon surfaced (both real, both fixed)
Even after the store, a global **Superset** would not work — two separate gaps neither UI path could set:
- **backend_id** (BACKEND-ID-1): Superset is a gateway; `backend_id:'superset'` is authoritative DATA (`resolveActiveBackends` + `toolPatternOf`). Neither JSON import nor the form set it → defaulted to armes → mis-routed. armes worked precisely because the default IS armes.
- **the `Accept` header + a form url-drop** (HEADERS-1): the endpoint needs `Accept: application/json, text/event-stream`; the guard blocked ALL headers wholesale; and the Add form validated only `name`, so re-entry silently dropped the URL (red url-less rows). Fixed by name/value-bounded guard + required-URL. The owner's final working recipe used **streamable-http** (SDK sends the right Accept by default) + `apiKeyRef:supersettoken` (token rotated) + `backend_id:superset`.
