The complete causal path of a single turn: what each module is, what it received, what it did (generic terms), and which module / interface / API it calls next — from the keystroke to the rendered answer. Colors mark the trust boundary an edge crosses. This is the human-readable companion to the (parked) OTel→Langfuse trace tree: every numbered step below is a span.

worked example "KB7 OEE this week"
browser ↔ vercel · user JWT browser ↔ supabase · RLS owner vercel → supabase · service-role vercel → MCP backends vercel → LLM providers deterministic in-process

role
The single tool round-trip: call → stream raw → format → ledger.

Connects + callTool (retry on transient transport errors, per-call timeout). 22
textStream loop chat.ts stream SSE text-delta
did
When the model finally writes prose, each chunk → fullText += chunk and res.write(text-delta). A 15s heartbeat keeps the socket alive across silent tool gaps.
next
→ post-stream validation.

⚠ trap — the blank-bubble path (the test's "No response generated")

If the model emits tool calls and then zero text deltas, fullText === ''. chat.ts has no deterministic fallback for that, so the client renders the literal string from cwfService (fullText || metadata.text || 'No response generated.'). This is a UI render, not a backend message — and it is exactly the parked Phase F item: a guaranteed final message.

23
runGroundingCheck _lib/grounding/groundingCheck.ts grounding · advisory
role
Mode-A deterministic check on the COMPLETE answer — never an LLM judge/score.
did
Runs on fullText + toolResultMetas + backendAuthority without re-running tools: empty≠zero / count-integrity / scope-divergence. It does not buffer or rewrite — first paint already happened. Violation → emit an error telemetry event (kinds/count only).
next
→ scope-divergence append.
24
scopeDivergenceNotice (Phase C) chat.ts · grounding correction SSE text-delta
did
On a scope_divergence verdict, deterministically appends a correction after the streamed text (finalText = fullText + notice) and streams it. It corrects the record; it can't un-paint what already streamed (that residual is the prompt-guards' + redundancy's job).
next
→ persist assistant message + done.
25
MessageRepository.insert _lib/persistence/… repo service-role
did
Enqueues the assistant message (finalText, toolCallCount, capped raw tool results, error flag) under the pre-minted id. Best-effort; a null service client is a silent no-op (the degradation contract).
next
→ done event.
26
done event chat.ts terminal SSE done
did
Writes the terminal done SSE: {text:finalText, toolCallCount, model, grounding, conversationId, messageId} — lets the client adopt ids and reconcile. (Mid-stream error → a terminal note + done(error:true) instead, so the socket never dangles.)
next
→ flush + end.
27
finally — flush chat.ts · Promise.allSettled serverless telemetry + persistence
role
Land all fire-and-forget writes before the function freezes.
did
Clears the heartbeat; Promise.allSettled([...telemetryWrites, ...persistenceWrites]) (never rejects; every repo method non-throwing) → res.end().
next
→ stream closes; control returns to the browser.

◆ this finally-flush is exactly where the parked tracing layer hooks

The OTel→Langfuse trace must force-flush spans here too — serverless can't rely on a background batch exporter. Every numbered step above maps to a span; the LLM/tool sub-tree (steps 18–21) comes near-free from AI SDK experimental_telemetry; steps 7/8/15/21/25 need manual spans. telemetry_events (the emits above) stays the separate RBAC-safe business ledger — not the debug trace.
