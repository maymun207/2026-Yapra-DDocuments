The owner's live MCP-panel review (queue #3's first concrete input) drove MCP-UX-1, and two deeper realizations fell out of it:

Automation is **source-blocked** (manual token acquisition). MCP-UX-1's probe now surfaces the window (401 → orange `auth`).
- **The multi-user gap** (owner: "end-users in USER mode — if they have no ARMES server, they get nothing"). Correct, and a real blocker: `mergeMcpServers` is **replace-by-id** (a personal row REPLACES a global entry whole — it cannot inject just a token), and the secret-guard blocks values from the world-readable global row → **a global server cannot carry auth at all**, and a fresh end-user with no personal ARMES row gets NOTHING. Today works only because ARMES is manually seeded per-user. (Owner-honest correction: an earlier "ARMES Personal-only is cleanest" answer was wrong for the end-user product.)

## §4 MCP-SECRET-REF-1 — the multi-user unblock (designed, phase-prompted, review pending)
Fix: a global server names an env var via a new `apiKeyEnv` field; the chat engine resolves the token SERVER-SIDE at request time via ONE shared `resolveAuthHeader` (the three inline `Bearer ${apiKey}` sites collapse to it). One global entry serves all users; the token lives only in env; **no `mergeMcpServers` change** (the global row is self-sufficient). §8.1 resolved **(A)** — Architect-verified that ARMES-MES already dials stdio→HTTP (no `StdioClientTransport`/`spawn`/`mcp-remote` in the chat path; `extractHTTPFromStdioArgs`→`connectMcp`), so a plain `sse` config with `apiKeyEnv` changes no runtime behavior beyond token source. **AG raised 3 refinements, all folded:** **#1 (security core, an Architect-missed hole)** — `^[A-Z][A-Z0-9_]*$` proves a valid env name, not a SAFE one; unbounded, a super_admin could set `apiKeyEnv:'SUPABASE_SERVICE_ROLE'` + `url:'https://attacker'` and exfiltrate a platform secret. Fix: the resolver honors ONLY `^MCP_[A-Z0-9_]+$` (platform secrets are structurally unreachable); token provisioned as `MCP_ARMES_TOKEN`. **#2** thread `apiKeyEnv` through MCP-UX-1's field-enumerating import path (strict parser/form/mask — else silently dropped). **#3** the probe uses the shared resolver + logs unset-env name-only. **Lane boundary held:** AG offered to draft the phase prompt; declined — the Architect writes the one gated phase prompt so the independent review-gate isn't collapsed. Side payoff: daily rotation becomes a ONE-place env-var update (not N user rows) and new users get ARMES automatically. **Status: phase prompt handed to AG; build + review pending next session.**
